# Tileベース設計拡張 & DFT規模増強ロードマップ・仕様検討TODO

本ドキュメントは、現行の 4コア RISC-V RV32I プロセッサ（`tiny_risc`）の仕様・ゲート規模の現状を整理し、**DFT（Design For Testability：スキャン挿入、ATPG、スキャン圧縮、モジュラーテスト）の本格的な評価・実験環境**を構築するための **「Tile（タイル）ベース設計への拡張」** および **「FF（フリップフロップ）数の増強計画」** をまとめた仕様理解・TODOリストです。

---

## 1. 現状の仕様・規模の整理（As-Is）

### 1.1 プロセッサ・SoC 構成
- **ISA**: RISC-V RV32I（非特権 Base Integer Instruction Set v2.1）
- **制御方式**: 6 ステートのマルチサイクル FSM（`FETCH_REQ`, `FETCH_WAIT`, `EXECUTE`, `MEM_REQ`, `MEM_WAIT`, `FAULTED`）
- **メモリ構成**: 共有 ROM（4KiB）および共有 RAM（4KiB）
- **バス調停**: 命令バス・データバスにそれぞれ 4 入力ラウンドロビン調停器（`rv32_mem_arbiter`）を配置
- **検証実績**: 公式 `riscv-tests` (RV32UI) 全 38 テスト 100% 合格、4 コア並行同期テスト合格

### 1.2 現行のゲート規模・FF 数内訳
| 構成ブロック | ASIC 規模 (NAND2等価 / GE) | フリップフロップ数 (DFF) | 主な構成要素 |
| :--- | :---: | :---: | :--- |
| **レジスタファイル (`regfile`)** | 約 7,500 〜 8,500 GE | **992 FFs** | 31×32bit DFF、2 ポート 32:1 読出 MUX |
| **演算器 (`alu`)** | 約 1,600 〜 2,200 GE | 0 FFs | 32bit 加減算器、バレルシフタ、比較器、論理演算 |
| **デコーダ・即値 (`control`, `imm_gen`)** | 約 250 〜 300 GE | 0 FFs | 組み合わせ論理デコーダ |
| **トップ制御・データパス (`tiny_risc`)** | 約 2,000 〜 2,500 GE | **67 FFs** | PC (32), IR (32), FSM (3), PC加算器, アライナ |
| **CPU コア 1 基 小計** | **約 11,000 〜 13,500 GE** | **1,059 FFs** | 1 Hart |
| **4 コア CPU サブシステム (4 Harts)** | 約 44,000 〜 54,000 GE | **4,236 FFs** | 4 Harts |
| **バス調停器 2 基 (`rv32_mem_arbiter` × 2)** | 約 700 〜 900 GE | **10 FFs** | 各 5 FFs（busy, owner, last_grant） |
| **SoC 合計（メモリセル除くロジック部）** | **約 4.5 万 〜 5.5 万 GE** | **約 4,246 FFs** | 4 コア + 調停器 |

### 1.3 DFT テストベッドとしての現状の課題
1. **FF 数が少ない（約 4,200 FFs）**:
   - 商用・研究用スキャン圧縮（EDT / TestKompress 等）で 10x〜30x の圧縮効果を測定するには規模が小さく、スキャンチェーン長が数十〜百段程度にしかならない。
2. **メモリ BIST（MBIST）対象の不在**:
   - 現在のメモリはレジスタ配列（FF展開）またはシミュレーションモデルであり、ファウンドリ SRAM マクロに対する March テストや冗長救済（BIRA）の検証ができない。
3. **階層型 DFT（Hierarchical DFT / IEEE 1500）の検証環境がない**:
   - コアがフラットにバス調停器にぶら下がっており、独立したテストラッパー境界（Test Collar）を持たない。

## 2. Tile（タイル）ベース拡張のアーキテクチャ構想（To-Be）

### 2.1 1 Tile の構成定義
各コアを自己完結した **Tile** としてカプセル化し、タイル単位でのスケーリングと階層テストを可能にします。

```
+-------------------------------------------------------------------------+
| [Tile n]                                                                |
|                                                                         |
|  +---------------------------+       +-------------------------------+  |
|  | tiny_risc Hart (1,059 FFs)| <---> | Tile Local Memory (TCM / FIFO)|  |
|  | - Regfile (992 FFs)       |       | - 命令/データローカルバッファ |  |
|  | - ALU, Control, FSM       |       +-------------------------------+  |
|  +---------------------------+                      |                   |
|               |                                     v                   |
|               |                      +-------------------------------+  |
|               +--------------------> | Tile Peripherals (500~800 FFs)|  |
|                                      | - Mailbox / Message FIFO      |  |
|                                      | - Local Timer & CSR           |  |
|                                      +-------------------------------+  |
|                                                     |                   |
|  +--------------------------------------------------v----------------+  |
|  | Interconnect Router / Interface (800~1,500 FFs)                   |  |
|  | - 2D Mesh NoC Router または クロスバーIF                         |  |
|  | - 各ポート送受信 FIFO (32bit x 4~8段 x 5ポート)                   |  |
|  +-------------------------------------------------------------------+  |
|                                     |                                   |
|  ====================== [IEEE 1500 Wrapper Collar] ===================  |
|  | WBR (Wrapper Boundary Registers) & Wrapper Instruction Register   |  |
+-------------------------------------------------------------------------+
                                      |
                           外部メッシュ配線 / 隣接 Tile
```

### 2.2 Tile 構造がもたらす DFT メリット
- **モジュラーテスト & パターン再利用（Broadcast Test）**:
  - 同一の Tile 向けに生成した ATPG テストパターンを全 Tile に同時ブロードキャストし、テスト時間とテストデータ量を激減させる検証が可能。
- **IEEE 1500 ラッパー（In-test / Ex-test 分離）**:
  - **In-test**: Tile 内部のロジック・スキャンチェーンの独立テスト。
  - **Ex-test**: Tile 間の NoC 配線・インターコネクトの縮退/遅延故障テスト。
- **Low-Power DFT / 電力インターリーブ**:
  - テスト時の過剰消費電力（IR ドロップ）を抑えるため、Tile ごとにスキャンシフト/キャプチャのタイミングをずらす電力制御テストが可能。

## 3. FF 数増強シナリオ & スケール試算

### 3.1 1 Tile あたりの FF 増加要素
1. **NoC ルーター（Network-on-Chip Router）**:
   - 各ポート（Local, North, South, East, West）に 32bit × 4〜8 段の FIFO を配置 $\rightarrow$ **+800 〜 1,500 FFs**
2. **Tile 内 Mailbox（メッセージ通信 FIFO）**:
   - コア間非同期/同期メッセージング用送受信 FIFO（32bit × 16段） $\rightarrow$ **+500 FFs**
3. **ローカルペリフェラル（タイマー、CSR、割込制御）**:
   - 64bit サイクル/リアルタイムカウンタ、コンペアレジスタ、制御フラグ $\rightarrow$ **+200 〜 300 FFs**
4. **ハードウェア乗算器（M拡張 乗算パイプラインレジスタ - オプション）**:
   - 32×32 Booth/Wallace 乗算段間レジスタ $\rightarrow$ **+100 〜 200 FFs**

$\Rightarrow$ **1 Tile あたり：約 2,500 〜 3,500 FFs（約 3 万 〜 4 万 GE）**

### 3.2 全体規模シミュレーション
| 構成 | 配置グリッド | 想定 FF 数 | ASIC ゲート規模 | 主な DFT 評価ターゲット |
| :---: | :---: | :---: | :---: | :--- |
| **4-Tile** | 2 × 2 Grid | **約 1.2 万 〜 1.4 万 FFs** | 約 12 万 〜 15 万 GE | 複数スキャンチェーン（8〜16本）の基本検証 |
| **8-Tile** | 2 × 4 Grid | **約 2.5 万 〜 2.8 万 FFs** | 約 25 万 〜 30 万 GE | **スキャン圧縮（EDT 10x〜20x）、ATPG 圧縮率評価** |
| **16-Tile** | 4 × 4 Grid | **約 5.0 万 〜 5.6 万 FFs** | 約 50 万 〜 60 万 GE | **本格的階層型 DFT、IEEE 1500、ブロードキャスト** |
